1 Overview

The Emplinx AI Assistant is an embedded chat widget available to every logged-in user across the Emplinx HRMS. It answers HR-related questions using the user's own live data — leave balances, payslips, attendance, shift details — and provides verified step-by-step navigation guidance for common tasks.

⚡ Key Characteristics
  • Role-scoped: What the AI can see is determined server-side from the logged-in user's role and company. An employee can never retrieve another person's data; HR/CEO can see company-wide aggregates.
  • Privacy-first: Sensitive values (names, dates, amounts) are replaced with typed placeholders like [[NAME1]] before leaving the server, and swapped back after the LLM responds. The model provider never sees raw PII.
  • Server-side proxy: The API key lives in AISettings and never reaches the browser. The ai_chat view proxies requests server-side.
  • Action-capable (optional): Companies can choose an action level — from "guidance only" up to "AI can approve/reject pending leave requests" — clamped to the platform owner's ceiling.
  • OpenAI-compatible: Works with any OpenAI-compatible API — Groq, Mistral, OpenRouter, or self-hosted Ollama.

2 Features by Role

Data scope is enforced server-side by the caller's role. The AI never sees data beyond what the logged-in user is authorised to access.

👤 Employee

Own data only

  • Own name, job role/position, department, shift, reporting manager
  • Leave balance per type (available days + carryforward)
  • Last 3 payslips (gross pay, deduction, net pay, status)
  • Last 14 days of attendance (clock-in, clock-out, hours worked)
  • How-to guides for all self-service tasks

🏢 HR / CEO

Everything Employee sees + company-wide stats

  • All employee-scoped data above
  • Active employee headcount
  • Pending leave request count (IDs listed at Execute level)
  • Total payslips generated company-wide + most recent period
  • Employees with active contracts (eligible for payslip generation)
  • Company-level action level and its capabilities/restrictions

The "employee" context is built from _employee_context(); HR/CEO additionally get _company_context() aggregates. See subscriptions/ai_assistant.py.

3 How-to Guidance

The assistant has 18 verified step-by-step UI guides written from the actual sidebar and templates of Emplinx. The model is explicitly instructed to never invent UI steps — every button name, menu location, and prerequisite is real and tested.

📋 Verified Emplinx How-to Guides
  1. Apply for leave: sidebar Leave → Apply Leave → Create button → pick leave type + dates → Save. Your manager approves it under Leave → Leave Approval.
  2. Approve/reject leave (managers/HR): sidebar Leave → Leave Approval → open the request → Approve or Reject.
  3. Generate payslips (HR/admin): FIRST the employee must have an ACTIVE contract (Payroll → Pay Register → Create, set status Active). Then sidebar Payroll → Payslips → Actions button (top right) → Generate. Pick employees + period → confirm.
  4. View own payslips: sidebar Payroll → Payslips (employees see their own).
  5. Submit an expense/reimbursement: sidebar Payroll → Expenses → Create.
  6. Form 16: sidebar Payroll → Form 16.
  7. Check in/out (web): the Check In / Check Out button in the top navbar.
  8. View attendance: sidebar Attendance → My Attendances (own) or Attendances (HR/managers, company-wide).
  9. Fix a wrong attendance entry: sidebar Attendance → Attendance Requests → Create.
  10. Request a shift change: sidebar Employee → Shift Requests → Create.
  11. Add a new employee (HR/admin): sidebar Employee → Employees → Create button → fill personal info → then open the employee and complete Work Info (department, job position, shift, reporting manager, company).
  12. View employee list: sidebar Employee → Employees.
  13. Org chart: sidebar Employee → Organization Chart.
  14. Raise a helpdesk ticket: sidebar Support → Tickets → Create.
  15. FAQs: sidebar Support → FAQs.
  16. Company settings (HR/admin): gear icon (top right) → Settings.
  17. Update own profile: click your avatar (top right) → My Profile.
  18. Pay Register / Contracts: sidebar Payroll → Pay Register → Create (set status Active for payslip eligibility).

The system prompt includes these guides verbatim. The model must reference them exactly — any task not covered results in "I'm not sure of the exact clicks" and a suggestion to raise a helpdesk ticket.

5 Security Architecture

  • API key server-side only — The API key is stored in AISettings (Django DB, encrypted at rest) and never reaches the browser. Every LLM request is proxied through the ai_chat view.
  • Data scope decided server-side — What data the model sees is determined from the logged-in user's own role + company, never from anything the client sends. An employee's request can only ever be built from that employee's own rows.
  • Cross-tenant impossible by construction — Every queryset is filtered by the caller's company. A user from Company A can never see Company B's data. No tenant-scoped data leak path exists.
  • Privacy tokenization — Sensitive values (names, dates, amounts) are replaced with typed placeholders like [[NAME1]], [[MONEY5]], [[DATE8]] before the request leaves the server. The LLM only ever sees placeholders; the real values are substituted back into the reply here, after the LLM responds. Any placeholder the model didn't echo back verbatim is stripped, not leaked.
  • Prompt-injection guard — If a prompt-injection attack causes the model to echo its own instructions or context block, the server detects this ("=== CONTEXT" in raw_answer) and returns a refusal message.
  • Off-topic refusal — The system prompt defines clear in-scope (HR data, Emplinx usage, workplace topics) and out-of-scope (coding, trivia, essays, news) topics. The model is instructed to politely refuse off-topic questions.
  • Wellbeing-aware handling — If the user expresses serious stress, burnout, hopelessness, or any hint of self-harm, the model is instructed to acknowledge their feelings first, suggest talking to their manager/HR or a mental health helpline, then address the HR question if relevant.
  • Session-scoped chat memory — Conversation history is stored in the browser's sessionStorage only (never persisted server-side). It auto-expires after 8 hours. A Clear button lets users wipe their conversation at any time. History is capped to the last 6 turns, each message clamped to 1,000 characters.
  • Server-side re-validation for actions — The LLM merely proposes an action (a JSON line like EMPLINX_ACTION={"action":"approve_leave","id":42}). The server re-validates: role check, company scope, request existence, current status, before executing through the same Django views a human click would hit. Nothing the model says alone changes data.
  • Output length & rate limits — Input messages are capped at 2,000 characters. The LLM response is limited to 600 tokens. The conversation history is limited to the last 12 messages (6 turns).

Tokenization Example

Before tokenization (server-side only, never sent to LLM):

Leave type Sick Leave: 12 days available, 2 days carried forward.
Payslip 2026-06-01 to 2026-06-30: gross ₹85,000, deduction ₹12,500, net pay ₹72,500, status confirmed.
Attendance 2026-06-30: in 09:15, out 18:30, worked 8.5 hours.

Sent to LLM (tokenized):

Leave type [[LEAVETYPE2]]: [[DAYS3]] days available, [[DAYS4]] days carried forward.
Payslip [[DATE5]] to [[DATE6]]: gross [[MONEY7]], deduction [[MONEY8]], net pay [[MONEY9]], status [[STATUS10]].
Attendance [[DATE11]]: in [[TIME12]], out [[TIME13]], worked [[HOURS14]].

After LLM responds: The server swaps each placeholder back to the real value before the reply reaches the browser. Any leftover brackets (from model-invented tokens) are unwrapped so real words are never blanked.

6 Admin Setup

🔐 Platform Owner

Configured at /manage/ai-settings/

  • Enable/disable the assistant platform-wide
  • Set API base URL (any OpenAI-compatible endpoint)
  • Set API key (stored server-side only)
  • Choose model name (e.g. llama-3.3-70b-versatile)
  • Per-role toggles: allow Employee / HR / CEO
  • Set the platform ceiling for action levels — no company can exceed this

🏢 Company Admin

Navigate: Settings → Integrations → AI Assistant

  • Pick an action level for the company from the allowed options
  • Options are clamped to the platform owner's ceiling
  • Only visible to users with base.change_company permission
  • Level is stored on the Company model as ai_action_level
⚙️ Integration Settings Sidebar Entry

The AI Assistant settings link is registered in base/sidebar.py under the Integrations section, alongside Gdrive Backup, LinkedIn, LDAP, Google Meet, and WhatsApp. The accessibility function checks for base.change_company permission.

Template: subscriptions/ai_settings.html (owner) and subscriptions/company_ai_settings.html (company admin, extends settings.html).

🧠 Model Behaviour Summary
  • In scope: user's own HR data, Emplinx usage guidance, general workplace/HR questions
  • Out of scope: coding, math homework, trivia, essays, world news — politely refused
  • Must not: invent UI steps, claim to execute actions it can't, refer to "CONTEXT" or internal instructions, create bracketed tokens around plain values

  • Token handling: must copy tokens exactly ([[NAME1]]) character-for-character, never paraphrase or reformat them
